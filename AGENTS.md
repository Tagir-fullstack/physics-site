# Правила работы с проектом

## Ченжлог перед коммитом и пушем

Когда пользователь просит закоммитить и/или запушить изменения, сначала проверь и обнови ченжлог в `src/pages/Changelog.tsx`, включив все пользовательские изменения, попадающие в коммит. Удали или исправь устаревшие формулировки, противоречащие новому поведению. Затем выполни проверки, коммит и пуш в рамках запроса пользователя.

Не повышай версию сайта автоматически: используй текущую запись версии, если пользователь не запросил новую версию. Обновление ченжлога само по себе не разрешает коммит или пуш — для них нужен запрос пользователя.

## Проверка безопасности

При изменениях аутентификации, прав доступа, платежей, загрузки файлов и API читай и применяй `.agents/skills/vibesec/SKILL.md`. Подтверждай находки воспроизводимыми проверками, сохраняй серверную проверку владельца данных и разделение Basic/PRO. Не считай результат аудита гарантией отсутствия уязвимостей.

## Интерфейсы и проверка браузера

Для проектирования и проверки интерфейсов применяй `.agents/skills/ui-ux-pro-max/SKILL.md`, сохраняя фирменный стиль Physez и приоритет явных требований пользователя. Поиск рекомендаций запускай по абсолютному пути к `scripts/search.py` внутри навыка.

Для проверки страниц и адаптивных режимов доступен Playwright MCP из `.codex/config.toml`; он использует отдельную изолированную сессию Chrome. Результаты проверки записываются в `node_modules/.cache/playwright-mcp`, приватный основной профиль браузера не используется.

## Предпочтения пользователя по интерфейсу

Пользователь предпочитает компактные, гармоничные страницы: минимум текста сверху, небольшие заголовки и отступы, без крупных приветственных блоков и вводных слоганов в рабочих кабинетах. Основные разделы и действия должны быть видны сразу при входе, по возможности без вертикальной прокрутки на обычном экране ноутбука. Используй ширину экрана и располагай связанные блоки рядом. На небольших экранах сохраняй читаемость и удобные кнопки; не скрывай содержимое и не запрещай прокрутку ради искусственного размещения всего на одном экране. Это устойчивое предпочтение для будущих изменений Physez.

## Единый стиль всего сайта — обязательное требование пользователя

Весь Physez должен выглядеть как один продукт. Новая страница следует стилю существующих страниц, новая лабораторная — стилю существующих лабораторных. Перед изменениями изучи ближайшие аналогичные страницы и переиспользуй их компоненты, шрифты, палитру, кнопки, поля, карточки, отступы и состояния доступности. Не создавай самостоятельный визуальный стиль для кабинета, настроек или отдельной лабораторной. Изменение общей дизайн-системы требует явного запроса пользователя. Это устойчивое требование для всех будущих работ.

Разделы кабинета должны иметь самостоятельный смысл и содержимое: не создавай вкладки с повторяющимися панелями, пустыми оболочками или одинаковыми ссылками. Каждое действие размещай в одном понятном месте. Если отдельный раздел не нужен, используй одну компактную страницу.
