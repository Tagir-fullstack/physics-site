# Вход и учебный профиль

`/register` и `/sign-in` показывают единый экран: Google или электронная почта с одноразовым кодом. Для нового email-аккаунта пароль обязателен: после ввода новой почты пользователь создаёт и повторяет пароль, затем подтверждает почту кодом. Google не требует отдельного пароля Physez. Телефон и выбор роли на экране входа убраны. Google возвращает в исходную лабораторную. В Clerk для development и production необходимо включить email_code для входа/верификации и сохранить обязательный пароль для регистрации; это настройка Clerk Dashboard → User & authentication → Password. Проверка почты и ограничение попыток остаются у Clerk.

Перед входом в четыре лабораторные `LabAccessGate` проверяет аккаунт и учебный профиль. `/education?next=…` запрашивает ФИО, вуз, ОП и преподавателя; гостя сначала направляет на вход. Для студента допускаются только B062, B063, B064, B076 и B057 (кириллическая В нормализуется). Если в вузе пока нет подтверждённых преподавателей, доступно самостоятельное обучение с последующим выбором преподавателя. Учебный профиль можно изменить в кабинете.

## Подтверждение преподавателя

Преподаватель указывает вуз и кафедру. Одна запись на Clerk user ID служит заявкой; исходный статус `pending`. Только серверный администратор может рассмотреть её на `/admin/teacher-reviews`. Очередь фильтруется по статусам и выдаётся страницами по 50. Отклонение требует причины. Повторное рассмотрение уже обработанной заявки возвращает конфликт. Проверка работы в вузе выполняется администратором; система не утверждает, что подтверждение получено от университета автоматически.

В справочнике для студентов видны только `approved` преподаватели. PRO не обходит подтверждение: создание тестов, загрузка и мониторинг проверяют обе предпосылки на сервере. Изменение вуза, кафедры или ФИО подтверждённого преподавателя снова требует одобрения. Подтверждение само по себе не выдаёт PRO; права владельца и администраторов сохраняются.

Преподавателю создаётся отдельный класс `Студенты · ФИО`. Студент включается в класс выбранного преподавателя на сервере. `/student/tests` показывает только назначенные ему тесты; прежние ссылки приглашений и уже выданные личные токены классов сохраняются. Для нового подключения по приглашению требуется аккаунт; членство связано с ID аккаунта, а не с введённым ФИО. Клиентские роли и метаданные Clerk не выдают доступ к чужим работам.

## Данные и миграция

`node --env-file=.env.local scripts/setup-education-profiles.mjs` создаёт исходную таблицу учебных профилей. `scripts/sql/teacher-verification.sql` добавляет поля проверки. `node --env-file=.env.local scripts/setup-teacher-verification.mjs` сначала только подсчитывает неверные ОП. С `--apply` сохраняет резервную копию затронутых полей в `/private/tmp` с правами 0600, очищает недопустимые текущие значения и нормализует допустимые. Номера вариантов, задания, ответы и результаты не меняются. Первоначальный владелец подтверждается только по явно настроенному OWNER_USER_IDS или ранее подготовленному seed ID, а не по имени из формы.

Справочник: 108 организаций из [реестра Национального центра развития высшего образования](https://enic-kazakhstan.edu.kz/page/Organizations_of_higher_and_(or)_postgraduate_education), получен 01.11.2026. Это снимок реестра; отсутствующие учреждения вводятся через «Другой вуз». Имя первоначального преподавателя Satbayev: «Аймұрза Тагир Айбекұлы».

## Проверки

`node scripts/test-education.mjs` и `node scripts/test-student-access.mjs` используют только временные схемы отдельного локального PostgreSQL на `/private/tmp`, порт 55439. Проверяются одобрение, запрет самостоятельного подтверждения, сокрытие неподтверждённых преподавателей, ОП, назначение тестов, сдача и отсутствие доступа к чужим данным. Рабочая база в тестах не используется.
