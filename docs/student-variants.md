# Постоянный вариант студента

- Источник номера: серверное поле `student_profiles.variant_number`, уникальная последовательность. Перед обновлением сервера выполнить `node --env-file=.env.local scripts/setup-student-variant-number.mjs`. Миграция добавочная и повторяемая.
- Общий профиль авторизованного пользователя — `/account`. Старый `/student/profile` ждёт загрузки авторизации, затем перенаправляет туда через replace. Отдельный экран данных/восстановления остаётся только для гостей и не называет их роль «студент».
- `AuthContext.profile.role` — выбранная роль в образовании (например, ассистент). Серверный `/api/account.role` — права доступа (user/admin/owner). Запись в `student_profiles` — ФИО, ОП и постоянный вариант участника работ, а не третья роль. Изменение этих данных не повышает права и не меняет образовательную роль.
- Фамилия, имя и ОП редактируются единой кнопкой в общем профиле. Если профиль работ существует, его ФИО имеют приоритет при отображении; сохранение обновляет его и поля first_name/last_name/full_name аккаунта. Не менять параметры и результаты уже выданных работ. Если одно из двух сохранений не удалось, явно сообщить о частичном результате и не закрывать редактирование.
- Профиль выдаёт `variantNumber` через `publicProfile`. Изменение ФИО/ОП, восстановление и привязка аккаунта не меняют номер.
- Новые лабораторные используют `currentStudent`, сохраняют отдельные параметры работы по `studentId`, отображают номер профиля. Внутренние коды и fingerprint работы не заменяют постоянный номер.
- Новые срезы используют `studentForWork` только после проверки права на начало/вход: сервер переносит `studentProfileId` и `variantNumber` в идентичность участника. Не принимать эти поля от клиента. Для нового гостя создаётся приватный профиль; коллизия ФИО требует восстановления, а не входа по имени.
- При ответе сразу с cookie профиля и сеанса сохранять оба заголовка `Set-Cookie`.
- Вариант не является паролем, кодом восстановления или разрешением на вход в срез. Зал ожидания, общий старт и отложенная публикация ответов остаются обязательными.
- Параметры и задания специфичны для работы. Старые попытки и варианты не пересоздавать; для старой попытки без номера в metadata показывать прежний код. Исправление отображаемых ФИО в мониторинге должно сохранять metadata профиля.
